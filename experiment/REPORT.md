## 1 Введение

В работе исследуется генерация исполняемых спецификаций TLA+ по текстовому описанию и конфигурации TLC. Проверяется синтаксическая корректность, выполнение проверяемых свойств и соответствие поведения эталону Gold.

Использована модель Qwen/Qwen2.5-Coder-14B-Instruct в формате GGUF с квантованием Q4_K_M. Локальный идентификатор Ollama qwen2.5-coder:7b-instruct-q4_K_M, число параметров по метаданным 7.6B. Версия Ollama 0.40.16. [Карточка модели](https://huggingface.co/Qwen/Qwen2.5-Coder-14B-Instruct).

Digest модели начинается с dae161e27b0e, полный идентификатор сохранён в model.json. Прогон начат 18.11.2026 06:17:06 UTC. Проверки выполнялись Java 22.0.2 и tla2tools.jar из локального набора данных. Точные запросы, ответы, команды и журналы сохранены в приложенных материалах.

Для 0 из 4 задач получены кандидаты, прошедшие SANY и TLC. Основной прогон дал отрицательный результат. В разделе 4 приведены фактические ошибки каждой задачи. Дополнительная ручная доводка позволила выполнить четыре модуля и исследовать содержательные расхождения в разделе 5.

## 3 Протокол генерации и проверки

Первый запрос для каждой задачи содержит только описание из выбранного поля датасета, требуемое имя модуля и полный исходный CFG. Применён zero-shot без примеров решений. В основном прогоне think = false. Пошаговые подсказки в запросы не добавлялись.

При неудаче следующий запрос содержит то же задание, предыдущий ответ модели и свежий полный вывод SANY либо TLC. Одна итерация соответствует одному запросу к API и одному полученному ответу. Лимит составляет 10 итераций на задачу. Успех TLC завершает генерацию этой задачи.

Параметры генерации одинаковы для всех задач. Temperature = 0.0, top_p = 0.95, top_k = 20, контекст 8192 токенов, лимит ответа 5000 токенов. Presence penalty = 0.0. Seed равен 1729 плюс номер итерации. Точные параметры сохранены в request.json.

Ответ сохраняется полностью. Автоматическое извлечение удаляет окружающий Markdown и пояснения, выделяя текст между заголовком MODULE и концом модуля. Формулы и операторы кандидата поступают в проверку непосредственно из ответа модели. Gold-модули читаются отдельным этапом проверки происхождения и сравнения. В запросы генерации поступают описание и CFG.

SANY запускается перед TLC. Успех SANY требует корректного завершения семантической обработки целевого модуля и отсутствия сообщений об ошибках. Успех TLC требует кода завершения 0 и сообщения Model checking completed. No error has been found. Проверка deadlock включена. CFG копируется из Gold без изменений. Для каждого запуска TLC используется один worker и фиксированный индекс fingerprint polynomial 0.

Лимиты времени составляют 25 секунд для SANY, 45 секунд для TLC и 600 секунд для ответа локального API. Истечение лимита фиксируется в журнале. Все таблицы ниже построены из results.json и журналов конкретного прогона.

### Генерация ConfigParams

Проверка передачи констант в конфигурацию. Четыре переменные инициализируются целым числом, строкой, model value и множеством. Next сохраняет состояние. Inv проверяет ожидаемые конкретные значения и различие двух model values.

На итерации 1 SANY сообщил лексическую ошибку на закрывающем Markdown-ограждении. Ответ содержал нестандартное завершение END MODULE вместо обязательного терминатора модуля. На итерациях 2-10 ограждение было убрано, но завершение END MODULE повторялось. SANY каждый раз ожидал продолжение тела или терминатор из знаков равенства. TLC не запускался. Причина неудачи связана с устойчивым воспроизведением неверного шаблона модуля даже после получения диагностического сообщения.

### Генерация Test1623

Обратный отсчёт натурального N. Единственная переменная x начинается с N, уменьшается на единицу при x > 0 и сохраняет значение при x = 0. Inv задаёт неотрицательность x. В конфигурации N = 4.

На всех десяти итерациях SANY сообщил об отсутствующих объявлениях операторов >, - и >=. Кандидат использовал арифметику без EXTENDS Naturals либо Integers. Структура модуля уже содержала корректный терминатор, поэтому диагностировалась семантика имён. Модель возвращала тот же набор формул без необходимого импорта. TLC не запускался.

### Генерация Bug2750

Ограниченный буфер производителей и потребителей. Состояние задаётся последовательностью buffer и множествами waitP и waitC. Процесс ожидает при заполненном либо пустом буфере. Успешная операция может разбудить ожидающий процесс противоположного типа. Конфигурация задаёт по два производителя и потребителя и ёмкость 1.

На итерациях 1-10 SANY останавливался на присваивании значения Producers внутри CONSTANTS. В TLA+ эта секция объявляет имена констант, а значения передаются через CFG. В тексте также присутствуют повторные определения p и c, неизвестный card, запись AND вместо конъюнкции, неопределённый vars и использование операций над множествами для последовательности buffer. Эти дополнительные дефекты выявлены чтением ответа. TLC не запускался. Модель смешивала синтаксис TLA+ с конструкциями обычных языков программирования.

### Генерация test10

Регрессионная проверка вычисления функций TLA+, обычных и кортежных аргументов, записей и EXCEPT с использованием @. Переменная x инициализируется TRUE и сохраняет значение. Содержательная часть проверяется в Inv через Assert и Print.

На всех 10 итерациях модель использовала -> в логических формулах, тогда как SANY ожидал допустимое продолжение модуля. Каждый ответ достиг лимита 5000 токенов, повторяя формулы о булевой переменной. Ответы обрывались до завершения модуля. Содержательные проверки функций, кортежных аргументов, записей и EXCEPT были вытеснены повторениями. Число ответов с ограничением длины равно 10, суммарное число сгенерированных токенов для этой задачи равно 50000.

## 5 Семантическое сравнение

Все Gold-модули проверены с исходными CFG. Для успешного кандидата применяется тот же CFG. Distinct States обозначает число уникальных состояний, Total States число сгенерированных TLC состояний с повторениями, Max Depth максимальную глубину полного обхода графа. Total States может включать несколько способов получения одного и того же перехода.

SANY отклонил исходные ответы до построения графов TLC. Поэтому количественное сравнение выполнено для кандидатов после ручных исправлений. Все четыре Gold-модуля прошли SANY и TLC.

В экспериментальном коде для проверки GoldSpec создаётся обёртка, наследующая сгенерированный модуль. Gold инстанцируется на тех же переменных через WITH. Проверяется PROPERTY GoldSpec при выполнении переходов кандидата. Если в Gold отсутствует оператор Spec, его формула восстанавливается из Init и Next как Init /\ [][Next]_vars. Для Bug2750 используется Gold!Spec.

Также реализовано обратное включение поведения. Gold запускается с PROPERTY ModelSpec, определённым через INSTANCE сгенерированного модуля на переменных Gold. Эта проверка выявляет потерянные переходы, которые могут пройти однонаправленную проверку благодаря допустимому stuttering.

Для сравнения выгруженных TLC графов DOT используются значения переменных. Сопоставляются начальные состояния, все достижимые состояния и уникальные пары состояний перехода. Имена переменных сопоставлены явно. Fingerprint узла используется только для чтения связей внутри одного файла.

Для кандидатов основного прогона проверки GoldSpec и ModelSpec не выполнялись вследствие ошибок SANY. Работа этих проверок подтверждена контрольными примерами в разделе 6.

После ручных исправлений ConfigParams и Test1623 имеют те же начальные состояния, достижимые состояния и рёбра, что и Gold. Обе проверки включения поведения проходят. Для этих конечных CFG получено совпадение исполняемой модели состояния.

В Bug2750 исправленный кандидат имеет одно состояние, а Gold имеет 36. Разность Total States составляет -95, Distinct States -35, Max Depth -6. Однонаправленная GoldSpec проходит, поскольку сохранение начального состояния допускается оператором [Next]_vars в Gold. Обратная проверка нарушается уже на шаге производителя p1. В контрпримере buffer меняется с <<>> на <<p1>>, что запрещено Next исправленного кандидата. В прямых DOT-графах Gold имеет 86 уникальных рёбер, кандидат одно ребро сохранения состояния. Эта собственная петля учитывается отдельно от неявного stuttering временной формулы.

Для test10 обе проверки включения поведения и сравнение графов проходят, но исправленный кандидат содержит только проверку x = TRUE. В Gold выполняется 31 проверка функций, кортежных аргументов, записей и EXCEPT, а исправленный кандидат содержит 0 вызовов Assert. Следовательно, совпадение поведения одной булевой переменной не подтверждает полноту регрессионных проверок. В этом примере семантическая оценка требует учитывать содержимое Inv и проверяемые вычисления.

Ручная доводка показала два разных источника ложного положительного вывода. Утрата переходов может пройти однонаправленную проверку благодаря stuttering. Пропуск вычислений внутри статического инварианта может пройти сравнение обоих графов и обеих временных формул.

## 6 Проверка экспериментального кода

Для исправленного кода выполнено семь регрессионных проверок. Проверены сохранение исходного тела модуля при удалении Markdown, обработка неверного текста и незавершённого модуля, отклонение семантической ошибки SANY, обнаружение изменённого перехода через GoldSpec и обнаружение потерянного countdown через обратное сравнение и разницу графов. Также проверено восстановление сохранённого ответа после прерывания без нового запроса к модели. Все семь тестов завершились успешно.

В контрольном отрицательном примере Next заменён на постоянное сохранение x. Однонаправленная проверка GoldSpec проходит, обратная проверка ModelSpec нарушается. Сравнение графов обнаруживает четыре потерянных состояния. В другом контрольном примере x увеличивается вместо уменьшения, что нарушает GoldSpec.

## 7 Вывод

В данном zero-shot эксперименте Qwen2.5-Coder-7B-Instruct Q4_K_M не получила исполняемую спецификацию за выделенный лимит на четырёх выбранных задачах. Основные причины наблюдаемых неудач состоят в неверной структуре модуля, пропущенных импортах стандартных операторов, смешении конструкций разных языков и повторении ошибочного ответа. При temperature = 0 исправление по одному последнему журналу часто сохраняло прежний шаблон. Для test10 дополнительно наблюдалось зацикливание генерации до ограничения длины. Все четыре эталона успешно прошли SANY и TLC. Семантическая корректность исходных кандидатов не подтверждена.

В дополнительном этапе четыре вручную исправленных модуля прошли SANY и TLC. После исправлений ConfigParams и Test1623 совпали с Gold на выбранных CFG. Bug2750 сохранил ошибочное отсутствие действий буфера, что обнаружили разница графов и обратная проверка. Для test10 совпадение графа и временных свойств сопровождалось пропуском регрессионных проверок функций. Поэтому прохождение SANY/TLC и одной GoldSpec требует дополнения анализом переходов в обе стороны и анализом содержательных проверок. Результаты генерации характеризуют выбранную модель, квантование и конкретный протокол.

Выводы о поведении ограничены выбранными конечными экземплярами CFG. Для параметризованной спецификации с произвольными множествами процессов и значениями констант требуется отдельное доказательство. Описания датасета могут опускать детали эталона, что влияет на возможность восстановить все операторы и регрессионные проверки.

## 8 Материалы и воспроизведение

Каталог coder-run содержит model.json, model-info.json, provenance.json, сводный results.json и отдельный каталог на каждую задачу.
