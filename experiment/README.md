# Лабораторная работа по семантической корректности TLA+

Вариант № 1 из задания в PDF. В REPORT.docx находится образец заполнения
отчёта с четырьмя или пятью условными успешными прогонами на задачу. Итерации,
ошибки и показатели кандидатов в образце вымышлены.

Результаты фактического эксперимента находятся в REPORT_ACTUAL.docx
и REPORT_ACTUAL.md. Скрипт build_report.py собирает эти файлы из журналов проекта.

Для основного эксперимента выбрана Qwen/Qwen2.5-Coder-7B-Instruct, GGUF Q4_K_M, через
локальный Ollama. Модель получает исходное описание и CFG.
Каждая повторная итерация добавляет предыдущий ответ и свежий журнал
SANY либо TLC. Лимит составляет 10 итераций на задачу.

Основной прогон завершён. Выполнены 40 реальных запросов, по 10 на задачу.
Все исходные кандидаты отклонены SANY. В repaired сохранены четыре
вручную исправленных кандидата, прошедшие SANY и TLC, и перечень исправлений.
Семантические расхождения Bug2750 и test10 разобраны в отчёте.

## Материалы нового прогона

- coder-run/model.json содержит digest и метаданные фактически вызванной модели.
- coder-run/model-info.json содержит полный ответ Ollama о модели.
- coder-run/results.json содержит сводку всех итераций.
- coder-run/audit.json подтверждает число запросов, единые параметры, соответствие
  сохранённых модулей ответам API и проверенные SHA-256 входов.
- В coder-run/<ID_имя>/description.txt сохранено исходное описание.
- В каталогах итераций 01, 02 и далее сохранены точные запросы, полные ответы,
  извлечённые модули, команды и журналы проверок.
- graph.dot содержит фактический граф TLC для запущенного кандидата.
- coder-comparison содержит проверки Gold, включение поведения в обе стороны
  и сравнение состояний и рёбер графа.
- notes.json содержит анализ ошибок и семантики.
- test-results.txt содержит результат регрессионных тестов кода эксперимента.
- repaired содержит вручную исправленные кандидаты и журнал их проверок.
- repaired/repairs.json фиксирует изменения и SHA-256 исходных ответов модели.
- repaired-comparison содержит отдельное сравнение исправленных кандидатов с Gold.

Успешный кандидат копируется в корень каталога задачи. Тела формул
сохраняются из ответа модели. Извлечение модуля удаляет окружающие
пояснения и Markdown.

## Повторный запуск

Команды выполняются из C:\projects\tla в PowerShell. Нужны Ollama,
установленная модель, Java и Python. Генерация, сравнение и тесты
используют стандартную библиотеку Python.

Установленная Java по умолчанию в PATH имеет повреждённый путь,
поэтому ниже указан проверенный исполняемый файл.

~~~powershell
$tlaJava = 'C:\Program Files\Java\jdk-22.0.2\bin\java.exe'
ollama pull qwen2.5-coder:7b-instruct-q4_K_M

python experiment/run_experiment.py --java $tlaJava --model qwen2.5-coder:7b-instruct-q4_K_M --output experiment/repeated-run

python experiment/compare_experiment.py experiment/repeated-run --java $tlaJava --output experiment/repeated-comparison

python -m unittest discover -s experiment -p test_experiment.py -v
~~~

Для каждого повторения задайте новые имена выходных каталогов.
Так сохраняются журналы предыдущего прогона.

Для продолжения прерванного прогона используйте тот же путь и --resume.
Сохранённый полный ответ будет проверен автоматически. Запрос, ответ на который
не сохранился, отмечается interrupted и учитывается в лимите.

Если модель переименовала переменные, compare_experiment.py принимает
--aliases с JSON вида {"Bug2750": {"buffer": "buf", "waitP": "waitingP"}}.
Сопоставление проверяется по фактическому коду и используется в INSTANCE
и при чтении DOT.

Отчёт собирается через build_report.py с python-docx из сохранённого
прогона, сравнения и notes.json. Для этого проекта использован
Python из bundled runtime Codex с установленным python-docx.

~~~powershell
$reportPython = 'C:\Program Files\WindowsApps\OpenAI.CodexPrimaryRuntime.v26-1119-907-0_26.1119.907.0_x64__3k8sg7r9htsxt\dependencies\python\python.exe'
& $reportPython experiment/build_report.py --run experiment/coder-run --comparison experiment/coder-comparison --notes experiment/notes.json --repair-comparison experiment/repaired-comparison
~~~

Для другого прогона следует обновить текстовый анализ notes.json
по его журналам перед сборкой отчёта.

Дополнительное сравнение ручных исправлений повторяется отдельной командой.

~~~powershell
python experiment/compare_experiment.py experiment/repaired --java $tlaJava --output experiment/repeated-repaired-comparison
~~~

Эти четыре исправленных кандидата прошли SANY и TLC. Для Bug2750 обратная
проверка обнаружила потерянные действия, а в test10 отсутствует набор 31
регрессионной проверки Gold. В отчёте результаты ручных исправлений
имеют отдельные таблицы.

## Сравнение поведения

Для проверки GoldSpec сгенерированный модуль наследуется обёрткой.
Gold инстанцируется на его переменных через WITH, затем в исходный CFG
добавляется PROPERTY GoldSpec. Для модулей без Spec используется
Init /\ [][Next]_vars. Обратная проверка запускает Gold и проверяет
ModelSpec сгенерированного кандидата.

Графы дополнительно сравниваются по значениям состояния, начальным
вершинам и уникальным ориентированным рёбрам. Это позволяет выявить
потерянные действия даже при совпадении агрегированных чисел TLC.
Для статического test10 в отчёте отдельно рассматривается полнота
проверок функций.

## Исправления кода

Исправлено копирование CFG в исходном run_experiment.py, из-за которого
shutil.copyfile возвращал строку, а дальнейший код вызывал read_text.
Добавлена передача предыдущего ответа при исправлениях и сохранение
полного ответа API, параметров, идентификатора модели и контрольных сумм.
Проверка SANY учитывает сообщения об ошибках вместе с кодом завершения.
Для TLC сохраняются DOT и команды запуска.

Предыдущая обёртка из compare задавала Next как Gold!Next /\ Model!Next
на независимых переменных. Новый compare_experiment.py проверяет
поведение на общих переменных и дополнительно выполняет обратную
проверку.

Каталоги generated, gold, compare, logs, prompts и saiga-run содержат
материалы предыдущей работы. Каталоги qwen35-run и qwen35-chat-run содержат
предварительные прогоны Qwen3.5-9B, завершившиеся ошибками синтаксиса.
Актуальный отчёт опирается на coder-run и coder-comparison.
